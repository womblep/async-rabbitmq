# Design: async-rabbitmq — Fiber-native Ruby AMQP 0-9-1 Client

## Vision

The canonical async-native AMQP client for the Ruby ecosystem. The RabbitMQ client
that every Falcon, async-http, and async-io user installs by default. Channels expose
stream-like interfaces (`#each`, `#write`). Backpressure is natural. Connection recovery
is built-in. The test suite is so complete it becomes the reference specification for
AMQP 0-9-1 behavior in Ruby.

No competing project exists. The gap is confirmed by search (2025).

## Scope — v1

**In scope:**
- Async-native API: `AsyncRabbitMQ::Session`, `::Channel`, `::Queue`, `::Exchange`
- Channel exposes duck-typed stream interface (`#each`, `#write`) — composable without Stream inheritance
- Automatic connection recovery with exponential backoff (initial 1s, max 30s, ±25% jitter, unlimited retries)
- Unconfirmed messages re-published automatically after reconnect
- Consumer re-registration on recovery
- Connection pool via `Async::Pool` (opt-in, `AsyncRabbitMQ::Pool`)
- Complete test suite against real RabbitMQ (Docker in CI, GitHub Actions)
- TLS support (direct TLS, min TLS 1.2, peer verify on by default)
- Publisher confirms (delivery tag tracking, `wait_for_confirms`)
- `basic.return` handling (mandatory flag)
- Channel-level flow control (`channel.flow`, `connection.blocked`)
- Soft vs. hard AMQP error handling with channel reopen
- Heartbeat bypass: heartbeat writes directly to socket via `Async::Semaphore`, never queued

**Not in scope (v1):**
- Bunny compat shim (v2)
- Metrics / instrumentation hooks (v2)
- CLI dev tools (v2/v3)
- Full Bunny test suite compatibility (v2)
- Topology re-declaration on recovery callback (v2)
- AMQP 1.0
- RabbitMQ management API

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│  Async-native API  (Session, Channel, Queue, Exchange)  │
│  Channel#each — yields deliveries (fiber-yielding)      │
│  Channel#write — publishes (duck-typed, composable)     │
├─────────────────────────────────────────────────────────┤
│  Connection Pool  (opt-in, Async::Pool-backed)          │
│  AsyncRabbitMQ::Pool.new(max: 5, url: "amqp://...")     │
│  pool.acquire { |session| session.open_channel }        │
├─────────────────────────────────────────────────────────┤
│  Connection Manager                                     │
│  Heartbeat: dedicated Async::Task, writes via           │
│    Async::Semaphore on socket (bypasses write queue)    │
│  Recovery: exponential backoff, re-registers consumers  │
│  TLS: direct connect, min TLS 1.2, peer verify default  │
│  Confirms: re-publishes pending on reconnect            │
├─────────────────────────────────────────────────────────┤
│  Frame Demultiplexer + Single Writer Pattern            │
│  Reader Task: manual 3-step frame read from             │
│    a plain TCPSocket/SSLSocket under the fiber scheduler│
│    (AMQ::Protocol::Frame.decode is an abstract stub)    │
│    → read_exactly(7) → decode_header → read_exactly(N)  │
│    → routes to per-channel Async::Queue                 │
│    → rescues AMQ::Protocol::Error + StandardError       │
│       → triggers recovery, never silent crash           │
│  Writer Task: drains Async::LimitedQueue (1024 frames)  │
│    → all writes except heartbeat go through this queue  │
├─────────────────────────────────────────────────────────┤
│  amq-protocol gem  (frame encode/decode — Bunny's gem)  │
├─────────────────────────────────────────────────────────┤
│  Ruby sockets + OpenSSL under the async fiber scheduler │
└─────────────────────────────────────────────────────────┘
```

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Channel stream interface | Duck-typed (`#each`/`#write`), NOT `Async::IO::Stream` inheritance | Channel is logical, not physical IO — inheritance was a category error |
| Write queue | `Async::LimitedQueue(1024)` | Prevents OOM under pub pressure; publish yields when full |
| Heartbeat write path | Bypasses write queue, direct socket write via `Async::Semaphore` | Heartbeats must never be starved by backpressure |
| Reader Task error rescue | Rescues `AMQ::Protocol::Error` + `StandardError` in outer loop | Prevents silent crash; always triggers recovery |
| Frame reading | Manual 3-step: `read_exactly(7)` → `decode_header` → `read_exactly(N)` | `AMQ::Protocol::Frame.decode` raises `NotImplementedError` — it is a stub |
| Confirms + recovery | Re-publish pending messages after reconnect | Transparent durability; no message loss on reconnect |
| wait_for_confirms + disconnect | Raise `AsyncRabbitMQ::ConnectionError`; caller retries after reconnect | Explicit contract; library re-publishes, caller re-waits |
| Soft error surface | Raise `AsyncRabbitMQ::ChannelError` (with `.code` and `.text`) | Consistent, explicit; caller rescues and opens a new channel |
| basic.return dispatch | Reader Task routes to per-channel handler in new `Async::Task`; warns if no handler | Never silently drop unroutable messages |
| Bunny shim | v2 | Untested shim in v1 was "theater" — v1 adopters don't need it |

## Frame Reading — Implementation Note

`AMQ::Protocol::Frame.decode` raises `NotImplementedError` — it is an abstract stub.
The Reader Task must implement manual frame reading:

```ruby
# Reader Task — correct frame reading pattern
loop do
  header  = @stream.read_exactly(7)                         # yields fiber
  frame   = AMQ::Protocol::Frame.decode_header(header)      # type, channel, payload_size
  payload = @stream.read_exactly(frame.payload_size)        # yields fiber
  @stream.read_exactly(1)                                   # frame terminator (0xCE)

  channel_queue = @channels[frame.channel]
  channel_queue&.push([frame.type, payload])
rescue AMQ::Protocol::Error, StandardError => e
  trigger_recovery(e)
end
```

Implementation note: the socket is a plain `TCPSocket` / `OpenSSL::SSL::SSLSocket`; under the
async fiber scheduler `IO#read` yields the fiber, so no `Async::IO::Stream` wrapper is needed.

Note: Large payloads (> frame_max) are split into multiple `body` frames by the broker.
The Reader Task must reassemble content-header + body frames before pushing to the
per-channel queue. The reassembly state machine is per-channel.

## Session Pool Interface

`AsyncRabbitMQ::Session` must implement the `Async::Pool::Controller` resource interface:

```ruby
class Session
  def reusable?   = open? && !@recovery_in_progress   # return to pool?
  def viable?     = open?                              # is socket alive?
  def concurrency = @negotiated_channel_max || 2047   # max concurrent channels
  def close       # existing close method — called by pool on eviction
end
```

## Error Classification

**Soft errors** (channel closed, connection stays alive, `AsyncRabbitMQ::ChannelError` raised):
- 403 ACCESS_REFUSED, 404 NOT_FOUND, 405 RESOURCE_LOCKED, 406 PRECONDITION_FAILED

The exception carries `.code` (integer) and `.text` (broker message). Caller can open a
new channel on the same session and retry.

```ruby
begin
  channel.basic_publish(...)
rescue AsyncRabbitMQ::ChannelError => e
  # e.code => 404, e.text => "NOT_FOUND - no queue 'foo'"
  channel = session.open_channel
  retry
end
```

**Hard errors** (connection closed, `AsyncRabbitMQ::ConnectionError` raised, must reconnect):
- 501-506, 530, 540, 541 (FRAME_ERROR through INTERNAL_ERROR)

## Publisher Confirms — Reconnect Behavior

If a disconnect occurs while `wait_for_confirms` is blocking:
1. `wait_for_confirms` raises `AsyncRabbitMQ::ConnectionError`
2. The library reconnects automatically (exponential backoff)
3. Pending unconfirmed messages are re-published on the new connection
4. The caller retries `wait_for_confirms` after the reconnect completes

```ruby
channel.confirm_select
channel.basic_publish(payload, exchange: "", routing_key: "my.queue")
begin
  channel.wait_for_confirms
rescue AsyncRabbitMQ::ConnectionError
  # Reconnect happened; library re-published automatically
  channel.wait_for_confirms  # wait for re-published messages
end
```

## basic.return Dispatch

`basic.return` frames arrive asynchronously on any channel. The Reader Task dispatches
them to the per-channel return handler in a new `Async::Task`. If no handler is
registered, a warning is logged — returns are never silently dropped.

```ruby
# Reader Task — basic.return routing
if frame_type == :basic_return
  handler = @channels[channel_id]&.return_handler
  if handler
    Async { handler.call(return_info, meta, payload) }
  else
    logger.warn("Unhandled basic.return on channel #{channel_id} — " \
                "register channel.on_return to handle unroutable messages")
  end
end
```

## API Surface (v1)

```ruby
# Connection + channel
session = AsyncRabbitMQ::Session.new(host: "localhost", port: 5672, tls: false)
session.connect                        # 30s timeout → ConnectionTimeoutError
channel = session.open_channel
channel.close

# Queue
queue = channel.queue("my.queue", durable: true)
queue.subscribe(manual_ack: true) { |di, meta, payload| channel.basic_ack(di.delivery_tag) }

# Publish
channel.basic_publish("payload", exchange: "", routing_key: "my.queue")

# Publisher confirms
channel.confirm_select
channel.basic_publish("payload", exchange: "", routing_key: "my.queue")
channel.wait_for_confirms             # yields fiber until all confirms received

# Return handler
channel.on_return { |ret, meta, payload| ... }

# Pool (opt-in)
pool = AsyncRabbitMQ::Pool.new(max: 5, host: "localhost")
pool.acquire { |session| session.open_channel.basic_publish(...) }
```

## Build Order — TDD

Each step ships with its integration test before moving to the next step.
This is not optional — it is how the test suite proves the protocol is correct.
Do not move to step N+1 until step N's test is green.

1. Frame demultiplexer + single-writer → **test:** basic.publish + basic.get round-trip
2. Connection negotiation (30s timeout) → **test:** TCP connect + AMQP handshake (plaintext + TLS)
3. Heartbeat (dedicated task + timeout) → **test:** connection survives idle; times out on 2x miss
4. TLS connect (direct, min TLS 1.2) → **test:** TLS handshake, peer verify
5. Channel open / close lifecycle → **test:** open, close, reopen
6. Channel error handling (soft/hard) → **test:** bad queue name causes ChannelError; channel reopens; hard error closes session
7. `connection.blocked` / `connection.unblocked` → **test:** publish yields on blocked; resumes on unblocked
8. Basic publish, get, ack, nack, reject → **test:** round-trip; ack/nack/reject all delivered
9. `channel.flow` (client-side throttle) → **test:** channel.flow(false) stops deliveries
10. `basic.return` handling → **test:** mandatory message to non-existent queue triggers on_return; warn if no handler
11. Queue declare, bind, unbind, delete, purge → **test:** each operation
12. Exchange declare, bind, unbind, delete (direct/topic/fanout/headers) → **test:** each type
13. Consumer (basic.consume, cancel, deliver) + per-delivery Async::Task → **test:** subscribe + delivery + cancel
14. `basic.qos` (prefetch) → **test:** prefetch_count respected under load
15. Publisher confirms + recovery → **test:** single/batch/nack; confirms survive reconnect
16. Multi-frame body reassembly → **test:** payload > frame_max split across frames, reassembled correctly
17. Concurrent channel stress → **test:** 100 channels publishing simultaneously, no frame interleaving

## Test Strategy

- Integration tests against real RabbitMQ (`rabbitmq:4-management-alpine` Docker, GitHub Actions; RabbitMQ 4.2+ rejects transient
  non-exclusive queues, so test queues are durable or exclusive)
- Per-test isolated vhosts (no test cross-contamination)
- Line coverage target: ≥ 90% (SimpleCov)
- Chaos tests:
  - Kill Docker container mid-consume, verify recovery and consumer re-registration
  - Fill write queue, verify heartbeat still fires (heartbeat bypasses queue)
  - TLS handshake failure on reconnect: surfaces as hard error, does not loop endlessly
- `connection.blocked` + publish: verify publish yields when broker sends blocked, resumes on unblocked
- Multi-frame body reassembly: payload 3× frame_max, verify received payload equals sent
- Concurrent channel stress: 100 fibers / 100 channels publishing simultaneously, no corruption
- Friday 2am test: 10,000 messages over 100 fibers, no message loss with confirms enabled
